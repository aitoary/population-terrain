# 注目地点ガイド v1

対象は既存の `public/data/miyako-population.geojson` の全692メッシュ。新たな外部データは取得しない。UIの値は検証済み `PopulationDataset.byId` から読み、人口・率の書式は既存関数を共用する。以下は選定時の原精度の記録で、配信値の別管理には使わない。

原本は `data/source-manifest.json` が固定する国土数値情報2024年版人口ZIP（SHA-256: `2ca30e11eaf5328098c93af59a11ec2f55e73a727c3359f297a4667c628c0d59`）。`npm run data:verify` は再取得・書換えをせず、公開GeoJSONの全7,612値をローカル原本の `PTN_YYYY` と照合する。

## 選定理由

| 名称・メッシュID | 原典ポリゴンの中心（経度, 緯度） | 選定理由 |
| --- | --- | --- |
| 中心部周辺 `594137744` | 141.934375, 39.647916667 | 全692件で2020年人口・2020→2070年の減少人数がともに最大。1,388.8053→414.4128人、974.3925人減、約70.2%減。人口集積の大きな柱の変化を入口にする。 |
| 市内北側 `594147883` | 141.978125, 39.739583333 | 中心部の候補から北へ約10km離れ、北緯39.71度より北の対象セルで2020年人口が最大。414.7807→116.7621人、298.0186人減、約71.8%減。中心部に近い減少率でも減少人数が違うことを比較できる。 |
| 内陸西部 `594132791` | 141.365625, 39.64375 | 中心部の候補から西へ約49km離れ、東経141.5度より西の対象セルで2020年人口が最大。39.3616→8.4915人、30.8701人減、約78.4%減。内陸の小規模なセルと人口集積のあるセルで、率と人数の違いを見る。 |

全域の人口規模・減少人数の上位と、北側／西側の候補を座標で比較した。減少率の上位3件ではなく、人口規模と地理的な広がりを重視した導入用の3例であり、市全体や地区全体の代表値ではない。

名称は既存の原典ポリゴンの座標に基づく大まかな位置表現。中心部周辺は既存の公式関連データで確認済みの宮古駅座標（`src/config/dataSources.ts`）から約1.4kmの位置。新たな町名・施設名や行政地区名を付けず、地区境界や特定施設の人口を意味しない。背景確認にも既存の地理院淡色地図を使用する。

人口は500mセル全体のPTN系列であり、PLATEAU建物の整備範囲や表示有無で選別しない。全カードの直下に、整備範囲外にも人口があり、建物非表示は無人・非居住を意味しない旨を表示する。

## 状態と操作

カード選択はAppの既存 `view` を `{ year: 2070, meshId }` に更新する。YearControlは既存の外部年変更・最終年の処理でタイマーを解除し、既存のURL effectが `history.replaceState` を行う。履歴・他クエリ・ハッシュの扱いを変えない。

カメラの要求回数だけを別に持ち、Cesiumの既存 `focusMesh` へ接続する。同じカードを押し直しても再移動できる。Viewer・地形の読込中は要求を保持し、準備後に移動する。地形取得失敗時は原典ポリゴンの周囲を各方向0.02度広げて上空から移動し、山地に近づきすぎることを避ける。人口柱の基準高を0で代用しない。通常の年・ID変更でカメラを再移動しない。

カードコピーは拡張した `ShareLink` と既存 `sharedViewUrl` を共用する。選択・再生・現在URLを変更せず、カードの2070年リンクをコピーする。Clipboard API失敗時は対象URLの読取専用欄を出し、現在のアドレス欄と取り違えない。

- `npm test`: 293件 / 12ファイル成功。3カードの元データ参照・表示書式・読込中の無効化を含む。
- `npm run test:python`: 16件成功。`npm run data:verify`: 原本との全7,612人口値・692形状の一致。原本・公開人口データの変更なし。
- `npm run build` と `npm run build:acceptance`: 成功。最終の通常 `dist/` は検査用のViewer参照を含まない。既存のCesium大容量チャンク警告は残る。
- `GUIDE_ACCEPTANCE=1 npm run test:guide`: 最終のChrome標準設定・専用受入buildでガイド5件成功（68.6秒）。3地点の人口・率、再生停止、2070年・選択ID・詳細・URL、実カメラの向きと距離、描画完了、同じカードの再移動、同じViewer/layerの維持、人口の再取得なし、3地点それぞれの実クリップボード・再読込復元を確認。コピー失敗・非対応からの再試行、地図エンジンの遅延読込中に選んだ地点への移動も確認。
- `npm run test:guide`: Chrome標準設定の通常本番buildでもガイド5件成功（約1分）。検査用参照を公開しない状態で、3地点・共有・読込中の選択を最終確認。
- 通常本番buildの既存ブラウザー9項目: 8件成功後、再生テストのクリック待ちと900msタイマーの競合を修正し、該当1件を再実行して成功。停止した実年の維持、キーボード手動変更、2070年で停止を検査する。既存の共有・全11年切替・0人口セル・データ失敗と再試行・Viewer再初期化を確認。
- `npm run test:headers`: ローカルWorkersの10項目成功（HTTP 200、MIME、配信バイト、ヘッダー）。所有するプロセスの終了を確認。

ブラウザーは1 worker、既存Chromeの一時プロファイルを使う。既存共有テストは従来のSwiftShaderを使い、ガイドはChrome標準の描画設定で確認する。実測はANGLE Metal / Intel Iris Plus Graphics 655、描画バッファ840×543。ガイドと既存共有の検査をそれぞれ300秒上限の別実行に分ける。実カメラ確認には専用の `dist-acceptance/` を使い、通常buildでは検査用参照が無いことを確認する。

強制SwiftShaderでは北側セルの人口geometry・選択・カメラは正しく、移動先の地形タイルの精細化が30〜45秒で完了せず、撮影前の待機がタイムアウトした（通信エラーなし）。Chrome標準設定に切り替えた北側・西側の2件は44.6秒で成功し、描画完了後の画像を確認した。タイムアウト回避のための地形・人口データの差替えや、アプリの描画品質の引下げは行っていない。
